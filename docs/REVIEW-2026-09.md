# ScholarPulse review — September 2026

## Scope and starting state

Reviewed the public web application, ranking research, snapshot/memory pipeline,
prediction evaluation, CI/deployment and optional Python analytics. Work started
from the fetched `origin/main` commit `bfb130875d88f7d497e9a2f2946e82444ba7248d`.
The older local checkout had existing uncommitted work and was preserved; the
release was prepared in an isolated Git worktree.

The deployed baseline contained 63 category snapshots, 6,300 category rows and
5,305 unique papers. It had four immutable prediction observations beginning
on 23 August 2026. Its latest successful feed refresh was 7 September; the
14 September workflow failed after upstream arXiv timeouts/throttling. The
baseline memory, snapshots and prediction log were downloaded before changes.

## Findings and resolution

| Area | Confirmed issue | Change |
| --- | --- | --- |
| Fusion | Partial lists used incompatible rank scales and did not explicitly weight actual coverage | Common percentile scale, centered missing evidence and coverage weighting |
| Age and discipline | Sparse fields could mix old and new papers; unrelated small fields were pooled | Per-category cohorts and 28-day citation-age comparison groups |
| Candidate coverage | Only the newest 100 could compete even when more had been harvested | Up to 500 recent candidates, with a bounded quiet-field fallback |
| Ordering | Rounded scores and source ordering could change otherwise reproducible results | Unrounded ordering, tied observations and stable ID tie-breaks |
| Explanations | Fused scores displayed a probability calibrated on a different metadata study | Relative standing, explicit uncertainty and actual external evidence |
| Historical research | Target papers entered their own dense author memory | Replay excludes target IDs; old numbers are archived with qualifications |
| Corpus memory | Duplicates in a batch, fixed ledger eviction and completed backfills could be recounted | Same-batch deduplication, two-year ledger, completed-month and age-horizon protection |
| History | Read failures could reset state, reruns overwrite claims, and a fixed cap discard immature cohorts | Fail-closed reads, first observation per version/day and no automatic history deletion |
| Evaluation | Cross-field pooling, cumulative outcomes and weighted positives could overstate evidence | Field/version separation, future citation gains, real observation thresholds and paired baselines |
| Discovery | A query was required; no most-cited mode; focused lists dropped cross-listings | Query-free field browsing, citation sort, URL-persistent filters and cross-listed papers |
| Search degradation | Fallback dropped field/author/sort constraints without clear disclosure | Preserve filters/order and show the reduced-coverage notice, including after pagination |
| Refresh resilience | An upstream outage could prevent publication or leave incomplete data | Restore prior state, bounded requests and dated carry-forward snapshots |

The legacy metadata coefficients and newcomer reservation are retained. An
approximate per-batch collaborator statistic cannot be called a lifetime coauthor
degree. Existing corpus counts cannot be retrospectively repaired from the
aggregate memory alone; this release prevents identified repeat-counting paths
without inventing a replacement history.

## Validation

- **66 web tests pass**, including mathematical invariants, sparse/invalid
  evidence, publication age, deterministic ordering, memory idempotency,
  cross-listings retained in other snapshots, primary/focused cohort selection,
  search constraints and evaluation gates.
- A subprocess integration test runs the actual snapshot builder and ranker
  through an upstream outage: histories, dates, cached counts and per-category
  scores survive; a rerun does not replace the day's prediction.
- **17 Python tests pass** under native Python 3.12.14, covering the existing
  unit, ingestion/resume, export/import, manifest and dashboard-publish paths.
- Web ESLint, TypeScript checking, Python Ruff and the production static export
  pass. The static export uses the actual `/Scholar-Pulse` base path.
- Chromium checks cover discipline onboarding, recommended/newest ordering,
  pagination, live query-free most-cited search, filter persistence after reload,
  unavailable-index fallback, saving, reading status, persistent notes and
  JSON/BibTeX export. Paper explanations and reference-list availability are
  inspected in the rendered interface.
- Desktop and 390-pixel mobile views are inspected, including Spanish/English
  and theme switching. Search and paper pages have no document-width overflow
  in the checked mobile states.
- The production baseline's four prediction entries remain object-equal after
  local ranking. Memory and count timestamps are preserved through fallback.

The [research protocol](../research/ranking/README.md) reports the separate
retrospective fusion experiment on 9,348 papers, the rejected equal-weight
candidate, training selection, source hash and all five missingness scenarios.
It is not a full-system or all-discipline accuracy estimate.

## Follow-up already encoded in the repository

The original first prediction reaches 90 days on **21 November 2026 at
15:06 UTC**. A Saturday workflow evaluates only mature observations and retains
the report. V2 has its own later observation window and is compared with the old
formula, recency and reference-only baselines on the same candidate set.

The evaluator declines a conclusion when outcomes are too sparse, any original
top-ten outcome is unavailable, or too few actual positive observations exist.
Fresh counts are required for v2 initial baselines; cached older counts are
never relabeled as new measurements. Repeated papers and overlapping cohorts
remain dependent observations.

## Practical limits

Scientific importance is broader than citations, and future impact remains
uncertain. Coverage and indexing latency vary by discipline; the metadata prior
was trained on older ML/NLP data. Search covers arXiv-indexed works, while local
fallback covers only saved recent candidates. arXiv can still prevent a fresh
harvest; the site will show the last available dated feed. Public APIs can also
leave citation graphs or related papers incomplete.

The optional Python production-scale embedding, clustering and GPU jobs were
not run. Their existing tests and lint passed, and those services are not in the
public site's serving or deployment path.
